# 数据生成、验证与人工审核

本次顺序：生成候选 → 程序校验 → assistant 复核与修正 → **你在 HTML 中人工审核** → 导出审核记录 → 上传服务器测试。人工审核尚未发生，页面不会预先勾选通过。

## 生成器做什么

`scripts/author_seed_bank.py` 保存首批 75 个场景种子。每个种子明确用户请求、是否调用、工具参数、模拟返回、参考答复和 train/dev 归属。`camera_sft.data generate/build` 将每个种子套入四种不改变意思的表达前缀，拼成 300 条完整对话。

例如“后置镜头、高画质、PNG 拍照”，生成的是：system → 用户请求 → camera_capture(rear, high, png) → 模拟 photo_id → 引用该编号的答复。不调用类只有 system → 用户 → 回答/澄清。训练只读取 messages，expected、审核意见和分组不会成为提示词。

当前生成器不调用大模型 API，也不自动创造全新语义。75 × 4 是受控扩展，不是 300 个独立场景。外部 agent 可按计划改写自然表达，必须保留已定意图及参数依据；新增语义应先新增种子与分组。

## 验证器做什么

| 层次 | 检查内容 | 不能由此推出 |
|---|---|---|
| 契约与结构 | 原 system/schema、已登记 ID、角色顺序、tool_call_id、必填参数/类型/枚举、无额外参数 | 请求的真实意图一定正确 |
| 标签与事实 | 调用、模拟返回、参考答复与当前种子一致；参数规范词出现在请求中；停止任务有对应事实 | 种子本身正确、否定范围正确 |
| 切分与污染 | 同源/同工具参数组合不跨 split、精确重复、原 50 题词面相似告警 | 隐藏盲测独立性或完全没有语义泄漏 |
| 发布完整性 | 源种子版本、train/dev 内容及文件 hash；审核 ID/样本 hash/结论/审核者/理由 | 审核者真实身份可被程序证明 |

程序本质上是“检查有没有遵守约定”，不是第二个语义老师。若种子写错，严格复制错误仍能过规则。参数词出现也不等于用户授权，例如“不要执行：后置镜头高画质 PNG 拍照”不能因参数齐全而调用；这类意图判断需要语义审核。

## 本次 assistant 复核结果

直接复核 75 个场景主体，并核对全部 300 条实际样本只增加四种中性前缀；这不是 300 次独立盲审。

- 原始版本 292 条保留，8 条退回修正，对应 `camera_status-01` 和 `camera_status-04` 各四条。
- 原问题：用户查询“当前设置”，模拟结果只有 `value: normal`，最终答复只有“状态正常”；没有回答所需设置内容。
- 修正：回填明确的模拟 profile/exposure/privacy，答复逐项报告；没有改变用户请求、工具参数、样本 ID 或 240/60 切分。
- 修订后 300 条均可进入人工审核与链路试训。同作者 assistant 复核记录的 `independent` 保持 false，不能充当你的人工签核。

原始数据：`data/mvp`。修订数据：`data/mvp-reviewed-v1`。逐种子理由、原始退回记录、修改前后 hash 与新版本结论：`data/reviews/author-v1/`。两版都可验证；发布清单绑定各自种子，不用新版种子替旧版验证。

当前仍有意保留的 MVP 局限：成功事件查询全部为空列表；存在性检测只有 false；停止 all 只覆盖一个活动任务；失败只有 device_unavailable；语言只扩前缀。它们不构成现有标签错误，但覆盖很窄，不能据此证明能力保持、真实闭环或达到 95%。

## 你怎样人工审核

打开 [300 条审核页面](数据生成与验证：300条审核记录.html)。文件自包含，不请求网络。75 张场景卡片各展示 4 条实际表达，共享工具、参数、模拟结果与答复；程序已确认每组这些字段一致。

1. 先读页面中的固定工具契约和 system，再看每组的四条原始请求。对停止任务必须同时读给定任务事实。
2. 检查该不该调用、参数是否唯一、结果与答复是否一致。特别看“否定/缺参/多个动作”、隐私 enabled、continuous 窗口时长，以及已标出的 8 条修正。
3. 每条标记通过或退回；确实读完同组四条后，也可点“本组四条通过”。退回须写原因。所有人工初始状态均为 pending；assistant 意见仅供参考。
4. 填写你的审核者标识，导出 `human-reviewed-v1.jsonl`。页面显示的本地缓存只是便捷草稿，导出文件才是可转移记录；也可重新导入同版本草稿继续审核。
5. 全部 300 条通过后，将文件放到仓库 `data/reviews/human-reviewed-v1.jsonl`，按 README 校验、prepare、训练。有人为修改样本时旧 hash 会失效，应修正数据并重新审核，不修改 hash 冒充通过。

页面允许导出尚未完成的审核草稿；含 pending/reject 的文件会被服务器脚本拒绝用于正式 prepare。若发现问题，把退回记录交回修正，再审核新版本。不要把退回样本删除来缩小分母。

导出中 `reviewer_kind=human` 和 `independent=true` 是你点击确认后的自述，并非系统验证了现实身份。尚未由你操作的记录保持 pending，绝不会由 assistant 自动变成人工通过。

## 服务器读取哪一份

上传整个仓库/交付 zip，以及你导出的审核文件，不能只传 train.jsonl：验证器还需要种子、契约、冻结回归文件与 manifest。代码、数据和 README 均已放在同一仓库；完整安装和训练命令只维护在 README。

人工全通过后采用 **不带 `--smoke`** 的 prepare/train。若只是先测作者复核版链路，可显式使用 `--smoke` 加作者复核文件；两种状态会写进实验清单，不能混称。
